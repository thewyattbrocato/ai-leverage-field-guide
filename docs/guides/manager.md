# Manager Track

*Run the decision loop on real decisions. Keep your judgment in the loop where it matters.*

---

## Why This Track

Managers decide. Every week: prioritize, resource, hire, cut, commit. The leverage loop turns
"reacting to Slack" into "running a decision system."

**Guides:** [Maker-Checker](../guides/maker-checker.md) + [Stop Conditions](../guides/stop-conditions.md)

**Time:** 3 weeks (Weeks 6–8)  
**Outcome:** A decision loop you use every week.

---

## The Decision Loop

```
1. CAPTURE   Dump context (constraints, stakeholders, options, fears, data)
2. STRUCTURE Run the "Decision Brief" prompt
3. JUDGMENT  You mark what's missing, biased, unverified
4. RE-RUN    Feed judgment back → refined brief
5. STOP      Every claim sourced; tradeoffs explicit; downside written
6. DECIDE    You make the call. Log decision + rationale.
7. RETRO     (1 week later) Was it sound? What would you change?
```

---

## Decision Brief Prompt

```
CONTEXT: I'm a [role] deciding on [decision] for [stakeholders].
RAW MATERIAL:
[paste: context, constraints, options, data, fears, stakeholders]

TASK: Produce a Decision Brief with:
1. The Decision (one sentence)
2. Context (what's driving this)
3. Options (2–4, with tradeoffs)
4. Data/Assumptions (what we know vs. assume)
5. Downside Scenario (what happens if wrong)
6. Stop Condition: Every claim sourced; tradeoffs explicit; downside written

CONSTRAINTS: Under 400 words. Plain language. No jargon.
```

---

## The Project (Weeks 6–8)

**Run the loop 2× on a real decision this week.** Then decide. Log it.

**Week 6:** Run the loop on Decision A. Log. Decide.
**Week 7:** Run the loop on Decision B. Log. Decide.
**Week 8:** Retro on both. What did the loop catch? What's next?

